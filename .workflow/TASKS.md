# Tasks

## Goal
`hooks-handlers/session-start.sh` carries a hand-written summary of the numbered guidelines in
`skills/coding-guidelines/SKILL.md`. The two are a derived copy and its source, and nothing in the
repository detects when they diverge - `CLAUDE.md` states this outright and asks for the summary to
be regenerated by hand. The outcome of this work is that a divergence stops being silent: someone
who renames, renumbers, adds or removes a numbered guideline and forgets the summary gets a red
test instead of a session that quietly teaches Claude the wrong list.

T1 reached that for the headings and left the taglines open - the half that carries the actual
rules. Demonstrated: inverting guideline 9's tagline in the handler, so every session is told to
swallow errors, leaves the suite reporting nine passes. The outcome T2 adds is that the copy stops
existing at all - the taglines live beside their headings in `SKILL.md`, the handler is generated
from them, and there is nothing left for drift to happen between. What neither task can catch is a
tagline that no longer describes its own section; that is editorial, and it stays uncovered.

## Constraints
Rigor: medium
Raised from `low` for T2, which changes the mechanism that hands every session its guidelines. T1
was judged under `low` and its pass stands as written. Pass 1 is spent, so T2 has passes 2 and 3.
The work must run from the repository with no network access. Bash and the tools the existing
suite already uses (grep, sed, printf, mktemp, awk) are the baseline; a Python interpreter may
also be used, since `CLAUDE.md` already requires one to verify this repository. Any tool that is
not already required somewhere in this repository counts as a new dependency and is not available.
Under T1, `hooks-handlers/session-start.sh` and `skills/coding-guidelines/SKILL.md` were the source
of truth and neither was to be edited. **T2 supersedes that** - it moves the taglines out of the
first and into the second, and makes the first generated. What replaces the rule is T2's
byte-identical criterion: the handler's stdout is what may not change, rather than the files.
The test must leave the working tree exactly as it found it.
Out of scope: whether a tagline still describes the section it sits under. T2 removes the copy that
can drift between two files; it cannot detect a tagline that has gone stale against its own
section, because a condensation has nothing to be mechanically compared against. That gap survives
this work, and `CLAUDE.md` says so.

## Technical requirements
Bash, run directly as `bash <path>`, matching `skills/commit/tests/test-commit-msg-hook.sh` in
invocation, output shape and exit convention. Runtime output is English and plain ASCII, per the
`language-check` convention this repository follows. One test file per target, so this target -
the `session-start` hook handler - gets exactly one file.

## T1 - Detect drift between the guideline summary and its source

### Requirement
A test exists that passes on the tree as it stands and fails whenever the numbered guideline list
in `hooks-handlers/session-start.sh` no longer agrees with the numbered headings of
`skills/coding-guidelines/SKILL.md` in count, number or title text.

The handler's own output must also still be what a SessionStart hook is allowed to emit: a single
JSON document on stdout carrying `hookSpecificOutput.hookEventName == "SessionStart"` and a
non-empty `additionalContext`, with exit status 0.

### Acceptance criteria
- `bash hooks-handlers/tests/test-session-start.sh` exits 0 on the tree as it stands, and prints a
  pass count in the same shape the commit-msg suite prints.
- The suite fails, with a message naming what diverged, under each of these three mutations applied
  to a copy of the sources rather than to the repository: a numbered heading renamed in
  `SKILL.md`; a numbered heading added to `SKILL.md`; a numbered heading removed from `SKILL.md`.
  Each mutation is exercised by the suite itself, so the negative case is demonstrated by running
  the suite and not by a human editing files.
- The suite fails when the handler emits invalid JSON, when `hookEventName` is not `SessionStart`,
  or when `additionalContext` is empty.
- `git status --porcelain` is empty after a run that started clean.
- Every non-ASCII character in the new file sits on a comment line: its runtime output - every
  `echo`, `printf` and embedded interpreter message - is plain ASCII English, and its comments are
  Traditional Chinese, matching the handler it tests. Checked per `skills/language-check/SKILL.md`
  rather than by a whole-file grep, which cannot hold alongside the Traditional Chinese comment
  requirement.

### Notes
`skills/commit/tests/test-commit-msg-hook.sh` is the pattern to follow and the only other test in
the repository; read it before designing anything. Its self-check convention, its temporary
directory handling and its counter output are all worth reusing rather than reinventing.
Numbered headings in `SKILL.md` are lines matching `^## <n>. <title>`. The corresponding lines in
the handler are the `\n<n>. <title> - ...` entries inside the single-quoted heredoc.

## T2 - Generate the guideline summary instead of hand-maintaining it

### Requirement
`hooks-handlers/session-start.sh` no longer holds a hand-written copy of the guideline summary.
The eleven `<n>. <title> - <tagline>` entries live in `skills/coding-guidelines/SKILL.md`, one
adjacent to each numbered heading, and the handler's `additionalContext` string is produced from
them by a generator that is checked in and re-runnable.

Nothing a session receives changes. The handler's stdout after this work is byte-identical to its
stdout before it.

### Acceptance criteria
- `bash hooks-handlers/session-start.sh` emits the same 2359 bytes it emits today, sha256
  `60998b93721851026e85ece9620e7d650769c1afe02cd357e5b37e432327178d`. This is the whole safety net
  for the migration: the eleven taglines move verbatim and nothing is re-authored.
- A generator is checked in, and re-running it against an unchanged `SKILL.md` reproduces the
  committed `hooks-handlers/session-start.sh` byte for byte. Name the command in its own header.
- `bash hooks-handlers/tests/test-session-start.sh` exits 0 on the tree as it stands, and its drift
  half is now regenerate-and-diff rather than a comparison of headings.
- The suite fails when a tagline is changed in `SKILL.md` and the handler is not regenerated - the
  case the heading comparison could not see. Exercised by the suite itself, on copies.
- The suite still fails under the three heading mutations T1 named, and still fails on invalid
  JSON, on a wrong `hookEventName`, and on an empty `additionalContext`.
- A `"` or a `\` in a tagline reaches the handler's output correctly escaped, and the handler's
  stdout still parses. `SKILL.md` already carries 12 lines containing `"`, so this is not
  hypothetical. Exercise it with its own case.
- `git status --porcelain` is empty after a run that started clean.

### Notes
The eleven taglines already exist, in the handler. Move them; do not rewrite them, do not improve
them, and do not derive them from each section's bold thesis line - that line serves a different
reader and differs from the tagline in six of the eleven sections.

Where the tagline sits inside `SKILL.md` is the one open design point. An HTML comment adjacent to
the heading leaves the rendered skill reading exactly as it does now, at the cost of being
invisible to a contributor editing that section. Propose something else through
`/claude-min-plugin:workflow change` if you can argue for it; do not pick silently.

The generator runs when somebody edits the guidelines, not at session start. The handler stays a
static heredoc: it runs on every session, and parsing or escaping performed there fails silently
into "no guidelines at all", which is the failure this line of work exists to prevent.
